# Demo Owner Review Follow-up R1 设计说明

## 目标与边界

在现有 `phase-3.7` / `junhui-demo-r2` 基线上，为固定十四模块中的 `hero` 增加可由后台维护的双语轮播；同时交付全中文后台操作手册、后台不可编辑内容审计、真实桌面/手机/后台截图和脱敏证据包。

本轮不增加新的业务内容模块，不修改十四模块顺序模型，不改产品、参数、正文、媒体关系或发布状态，不发布 Privacy，不启用 RFQ，不迁移数据库，不触碰原 `phase37` 环境，不 commit/push/merge/deploy。

## 方案比较

### 方案 A：扩展现有 HomepageLayout JSONB（采用）

在现有 `hero` 模块配置中增加 `slides` 数组，继续复用双语布局、乐观锁、草稿、认证预览、应用和恢复链路。优点是无需迁移和新内容库，权限、Revision 与 Audit 自动沿用；旧配置没有 `slides` 时仍按现有静态 Hero 渲染。

### 方案 B：新建 BannerSlide 业务表

数据更规范，适合未来独立排期、复杂投放和统计，但需要新实体、迁移、权限、发布与路由规则，超出本轮限定实施范围。

### 方案 C：前端写死轮播

实现快，但不满足后台 CRUD、双语、排序、启停和预览要求，因此不采用。

## 数据与安全设计

`hero.slides` 按数组顺序表示排序，每项包含：

- `id`：稳定的英文短标识；同一语言内唯一。
- `media_id`：现有公开媒体 UUID。
- `title`：当前语言主标题。
- `subtitle`：当前语言副标题。
- `cta_label` / `cta_href`：可同时填写或同时留空；链接只允许当前站点绝对路径，禁止协议、双斜杠和脚本 URL。
- `enabled`：是否进入公开轮播。

后台最多保存 5 项，允许暂时为 0 项以兼容旧数据和恢复流程。服务端保存前验证：仅 Hero 可携带 `slides`；ID 唯一；文本长度合规；CTA 成对；链接安全；引用媒体必须是 `public`、`ready`、`public-media` 桶中的图片。公开 DTO 只返回启用且仍合格的图片，不返回 `media_id`、对象存储字段、上传者或禁用项。

不修改数据库表或历史迁移；`schema_version` 保持向后兼容，由服务端稳定序列化新增字段。

## 后台交互

后台入口仍为“首页模块编辑器” → 选择“Hero 首页主视觉”。在原模块属性下增加“轮播项”区域：

- 新增、编辑、删除轮播项；最多 5 项。
- 上移、下移调整数组顺序。
- 启用/停用单项。
- 从现有公开且就绪的图片中选择素材并显示缩略图和文件名。
- 使用现有中文/English 标签切换当前语言文案。
- 保存草稿后，在现有认证 iframe 或新窗口预览；发布权限仍只由“应用布局”控制。

所有新后台提示使用中文；不暴露 UUID、JSON、桶名或对象键。删除采用本地表单移除，只有“保存草稿”后才持久化，仍可用“从应用版恢复草稿”撤销。

## 前台视觉与可访问性

采用用户确认的全宽沉浸式工业主视觉：现有深蓝网格和品牌色保持不变，图片铺满 Hero，左侧叠加深蓝渐变文字安全区，底部提供页码、进度、前后切换和暂停/播放。

- 2 项及以上启用项时每 6 秒自动播放；单项不自动播放。
- 鼠标悬停、键盘焦点进入、页面隐藏时暂停；离开后按原状态恢复。
- `prefers-reduced-motion: reduce` 时关闭自动播放和非必要过渡。
- 按钮、箭头、圆点具备可读中文/英文 `aria-label`，键盘可操作。
- 首张图 `eager`/高优先级，其余 `lazy`；SSR 仅预加载第一张启用轮播图。
- 375px 下标题、按钮与控件不重叠，图片使用裁切背景，文字保持可读。
- 没有合格启用轮播项时，完整保留当前静态 Hero 作为回退。

## 初始 Demo 轮播内容

通过当前后台草稿/预览/应用链路为 `zh-CN` 与 `en` 各配置 4 项，图片优先从现有 Demo 媒体中选择：

1. 螺杆与机筒精密制造 / Precision Screw & Barrel Manufacturing
2. 表面工程与工艺技术 / Surface Engineering & Process Technology
3. 制造能力与质量控制 / Manufacturing Capability & Quality Control
4. 面向应用的解决方案 / Application-led Solutions

文案只描述 Demo 导航意图，不写未经批准的产能、精度、认证或客户事实；每项继续标记为 Demo 素材。若现有媒体不合格，则不为凑数量修改业务记录，而是在报告中如实记录。

## 文档与审计口径

后台中文手册以实际菜单、字段、状态和建议操作顺序为主，覆盖用户要求的 12 章，并明确 Demo 当前 Privacy/RFQ 保护状态。

“后台不能修改”审计范围限定为当前公开官网中会影响品牌、业务内容、SEO/GEO、页面结构或正式上线的可见内容和关键配置；普通按钮标签、错误提示、开发测试文本不逐字计入。每一项包含位置、当前表现、不可编辑原因、改造建议、P0/P1/P2，并将“需真实资料”与“需开发功能”分开。

## 验证与证据

采用测试先行：先增加 API 输入/公开输出安全测试、前台轮播交互测试和后台编辑合同测试并观察失败，再写最小实现。完成后运行受影响 API、Admin、Website 测试、类型检查、lint/format check 与 build。

在独立真实 PostgreSQL / TEST ONLY 环境验证草稿、保存、fresh GET、预览、应用、恢复、无效媒体、禁用项和安全链接；在主 Demo 只通过后台正常操作配置四项，先留存快照，不运行 Seed/迁移。最终使用 1440 和 375 浏览器真实执行自动/手动切换、CTA 同源跳转、双语、后台增改删排启停与预览，截图统一来自最终运行版本。证据包排除密码、Cookie、Token、备份与客户资料。
